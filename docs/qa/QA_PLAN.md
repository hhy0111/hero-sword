# QA_PLAN.md

## QA 개입 원칙

- QA는 Gate 2부터 시작한다.
- 정상 동작 확인보다 깨지는 지점을 먼저 찾는다.
- 각 루프는 `문제 목록 -> 수정안 적용 -> 재테스트 결과 -> 남은 리스크`를 남긴다.
- 최소 3회 루프를 강제한다.

## 루프 구성

| 루프 | 시점 | 초점 | 산출물 |
| --- | --- | --- | --- |
| Loop 01 | Gate 2~3 | 코어 루프, 저장/복구, 상태 전이 | `QA_LOOP_01.md` |
| Loop 02 | Gate 4~5 | UI 혼란, 광고/IAP 동선, 반복 입력 | `QA_LOOP_02.md` |
| Loop 03 | Gate 5~6 | 릴리즈 후보, 아트/UI 상용 품질, 운영 누락 | `QA_LOOP_03.md` |

## 반드시 점검할 범위

- 정상 흐름
- 실패 흐름
- 경계값
- 빠른 연타
- 반복 진입
- 저장 후 복귀
- 앱 재실행
- 광고 진입/이탈/보상 미지급
- 네트워크 상태 변화
- 튜토리얼 중단 후 재진입
- 씬 전환 중 상태 꼬임
- UI 오해 가능성
- 아트/UI/연출의 상용 퀄리티
- 생성형 AI 특유의 어색함 여부

## 입장 조건

- 관련 기능의 입력값과 기대 동작이 문서에 정리되어 있어야 한다.
- Blocker가 있는 상태를 숨기지 않는다.
- 테스트 불가 항목은 `불가 사유`와 `필요 입력값`을 남긴다.

## 산출물 연결

- 테스트 상세: `TEST_CASES.md`
- 심각도 기준: `QA_SEVERITY_RULES.md`
- 결함 누적 기록: `BUG_LOG.md`
- 각 루프 기록: `QA_LOOP_01.md`, `QA_LOOP_02.md`, `QA_LOOP_03.md`
- 자동 smoke 실행: `npm run test:smoke`, `tests/playwright_smoke_actions.json`
