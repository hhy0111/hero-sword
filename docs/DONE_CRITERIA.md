# DONE_CRITERIA.md

## 공통 완료 기준

- 산출물이 실제 다음 작업자에게 연결된다.
- `[TODO]`, `[확인 필요]`, 리스크가 숨겨지지 않는다.
- 책임자와 갱신 대상 문서가 명시된다.
- QA 승인 전 최종 완료로 표시하지 않는다.

## Gate별 완료 기준

### Gate 0

- 프로젝트 입력이 문서화됨
- 비어 있는 값이 TODO/확인 필요로 분리됨
- 현재 상태가 분석됨

### Gate 1

- `PLAN.md` 작성 완료
- MVP 범위와 비포함 범위 분리
- 초기 리스크와 done 기준 등록

### Gate 2

- `CORE_LOOP`, `UI_FLOW`, `ART_DIRECTION`, `QA_PLAN`, `RELEASE_INPUTS` 생성
- 각 문서가 서로 참조되고 있다
- release_ops 입력 추적이 시작되었다

### Gate 3

- 작업 요청 템플릿으로 역할별 입력값이 정리되었다
- 저장 구조, UI 구조, 아트 규칙의 충돌이 정리되었다
- QA 기본 시나리오가 준비되었다

### Gate 4

- 핵심 루프가 실행 가능하다
- UI와 상태가 연결된다
- 저장/복구가 최소 한 번 검증되었다

### Gate 5

- QA Loop 3회 이상 기록 완료
- 각 루프마다 문제, 수정안, 재테스트, 남은 리스크가 존재한다
- Blocker 처리 여부가 표시된다

### Gate 6

- 광고/IAP/스토어 입력값 추적 표가 갱신되었다
- 사람이 넣을 값, 코드 연결값, 콘솔 입력값이 분리되었다
- Secret 정책 위반이 없다

### Gate 7

- `qa_agent` 승인 기록 존재
- 핵심 TODO와 잔여 리스크 정리 완료
- 파일 목록과 목적 요약 완료
